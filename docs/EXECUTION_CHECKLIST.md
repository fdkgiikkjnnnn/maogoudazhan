## T1. 建立 Cocos 底座与早期技术验证

- [ ] 固定 Cocos Creator 3.8.x LTS 补丁版本，建立最小 TypeScript 实时 3D 工程，记录实际工具版本。
- [ ] 玩法核心保持纯 TS；Cocos 表现与 PlatformAdapter 分离，核心不直接访问节点、系统时间或平台 API。
- [ ] Mac 上验证编辑器与 Web 预览，建立加载、准备、暂停、继续、结算和重开状态骨架。
- [ ] 用同一意图接口处理鼠标／触控；设置与存储失败可回退，前后台统一转成生命周期事件。
- [ ] 建立唯一固定步模拟时钟，出兵／移动／冷却／前摇／飞箭／施工统一接入。
- [ ] 先用空工程导出检查引擎包体与资源路径，再做最小资产加载；按 3.5MB 主包／18MB 总包内部目标分配抖音资源余量。
- [ ] 在已有且获准的环境分别做 Windows、Android、抖音最小技术样本；缺 Windows + VS、Android 工具链／设备、抖音工具／AppID 的端写“未验证”，不以 Web 代验。
- [ ] 切后台 30 秒返回：保持暂停，显式继续，无时间追补；连续重开 10 次无旧监听／事件。

通过标准：可用环境上的底座和生命周期有实际结果；三平台技术验证状态清楚。平台账号、商店材料和上传不属于本步骤。未获准的工具安装不执行；关键端仍未验证时，不宣称多平台底座全部通过，也不提前批量制作高成本资产。

## T2. 验证真实猫狗与动作

- [ ] 制作或取得一猫一狗基础资产，保留 Blender 源文件，验证 glTF／GLB 实际导入 Cocos；记录最小来源与条件待确认项。
- [ ] 在固定镜头下区分工程猫、盾猫、弩猫和普通狗。
- [ ] 验证共用骨架与装备挂点；先测弩射持物、狗走路／攻击／受击衔接，再测施工、盾击、退场，检查脚底、肩肘、尺度与权重。
- [ ] 两个同类实例同时播放不同动作，姿态互不串联。
- [ ] 同一 Cocos 构建可运行，记录实际网格、材质、纹理、角色数量与帧时间；两个静态模型不算全部动作完成。

通过标准：角色与动作清晰可用，持物不明显穿帮，实例独立。白模可并行用于规则验证，但不能作为最终猫狗试玩交付。无需先生成扩展兵种或先做安卓验收。

## T3. 做通施工与经济

- [ ] 准备／战斗阶段可制造；非法阶段、错误战位、钱不够、已占位均拒绝且不扣款。
- [ ] 接受时只扣一次、只锁一次；一次只有一任务。忙时可查看战位、价格和射程，仅禁止新制造且不排队；常驻目的地、进度与剩余时长。
- [ ] 前往中有固定取消入口，全额退款一次、解锁一次；施工开始后取消被拒绝。
- [ ] 工程猫走连续过桥的独立便道、不受伤不挡路；路径 ≤ 18、移速 6、施工 1.5 秒，单次目标 ≤ 4.5 秒；不做准备瞬移或阶段双移速。
- [ ] 完工前空位不参战；盾猫倒地仍占位，不能再造。
- [ ] 战斗清波时保留未完成任务；准备中继续，忙碌禁开下一波。
- [ ] 失败／胜利与完工同一步不产生幽灵单位；重开不带回旧任务。
- [ ] 首切片没有升级、拆除或支援入口。

通过标准：快速重复点击、资金不足、取消、清波、终局等操作均有唯一 taskId 与资金事件可核对；无重复扣款／退款、负余额或隐形排队。

## T4. 做通战斗、固定三波与结算

- [ ] 按主方案精确生成 8／10／12 只狗及对应出生时刻；组间空场不能提前清波。
- [ ] 盾猫最多挡 2 只；固定接敌槽互不重叠、位于攻击距离内。满额狗沿真实侧绕曲线，倒地释放、前后线独立，过线不回抓。
- [ ] 8 狗密集场景无明显穿人；权威位置、模型与箭代理一致，绕行按弧长维持移速；狗进入可攻击位置后首次等满 1 秒，盾只打自己所挡狗。
- [ ] 弩猫按最近水晶再 spawnId 选敌；换靶不返还冷却。
- [ ] 起手／放箭前校验目标，箭绑定 targetId；线段扫掠触达碰撞代理才扣血。
- [ ] 箭目标先死、超过 2 秒、清波或终局时正确清理；每箭仅命中一次，动画不重复扣血。
- [ ] 同一步按伤害／死亡、漏怪／水晶伤害、失败、清波／胜利顺序处理。
- [ ] 每狗击败奖励仅一次，漏怪不给击败奖励，每波 +30 仅一次。
- [ ] 清波后盾猫满血复活、水晶不恢复；第 3 波胜利或生命归零失败，终局停止模拟。
- [ ] 相同配置与输入重复结果一致，暂停时前摇／冷却／飞箭／施工均冻结。

通过标准：日志能用模拟时间、实体 ID、攻击／命中／死亡／奖励事件解释画面。重点复测“最后一狗死亡／漏怪”“水晶归零与清波同一步”“多箭打同一目标”，无双结算、回抓、穿透或不可见伤害。

## T5. 验证完整对局、布阵与经济

- [ ] 按“首波盾 + 弩，第二波加弩，第三波加盾”的候选顺序，真实玩完整局。
- [ ] 每波记录采购与位置、施工时长、击败／漏怪、水晶、资金和结果；验证至少一条稳定通关路径。
- [ ] 验算并实测初始 165：全歼累计 165／219／279、最终购齐后余 9；前两波累计漏 0／1／2／3／4 的边界分别覆盖。
- [ ] 验证第二波前余额 84−3a、买过第二弩后第三波前余额 69−3(a+b)；累计漏 3 时刚好可买末盾，累计 4 不能按原候选买齐。
- [ ] 比较双弩、前盾前弩、前盾后弩；至少一个可重复遭遇中盾降低漏怪，第二线实际接敌，不要求纯弩必输。
- [ ] 检查工程猫等待是否有价值；需要改善先缩路径、优化反馈，不加新系统。
- [ ] 计划让少量真实新手尝试识别职业、造猫、开波、取消和暂停，记录误触与疑惑；尚未测试时不编造人数或结果。
- [ ] 每次调整现有射程、移速、出兵密度、战位或资金后，复测完整三波并记录原因。

通过标准：真实猫狗同一构建有完整对局录像和逐波结果，混编可通关且职业与前后线作用可解释。算术不代替通关，概念图不代替操作；未达标保持未通过，不扩八波。

## T6. 交付本地完整试玩

- [ ] 同一构建包含桥地图、真实工程猫／盾猫／弩猫／普通狗、4 战位和完整 3 波。
- [ ] 从加载到准备、制造、开波、胜利／失败、重开均可实际操作。
- [ ] 核心资产未齐禁开波，加载失败可重试／返回；缺核心模型不以白模顶替，缺可选音效可静音；旧 sessionId 回调不污染新局。
- [ ] 暂停／后台 30 秒返回／显式继续正确，音频冻结；进程被杀或重载后清楚进入新局，手动退出提示结束本局，不伪装续局。
- [ ] 连续重开 10 次并复测终局、取消、目标死亡、加载中返回等边界，无旧箭／旧任务／旧监听污染。
- [ ] 验证 16:9、16:10、4:3、20:9，路线、四战位和水晶可见；安全区与面板不遮关键操作，主热区初始目标 ≥ 48 逻辑单位。
- [ ] 目标设备待选。完成加载后测首切片 17 个骨骼单位压力，连续 10 分钟记录设备、系统、运行环境、分辨率、画质、包体、平均 FPS、P95 帧时、> 100ms 长帧次数和峰值内存；初始目标平均 ≥ 30 FPS、P95 ≤ 40ms，首载独立记录。
- [ ] 提供真实可用的本地启动说明、构建标识、完整试玩录像和必要测试摘要。

通过标准：用户能本机从头玩到结算并重开，所有关键规则有实测结果；几何体演示、素材散图、静态截图或只有可旋转模型的页面不算完成。T6 是本地切片完成，不代表三平台全部验收、公开上线或平台审核完成。

## 三平台分别验收

最小技术风险已在 T1 提前检查；这里用完成的同一三波版本分别验收，不在商店上传后才测。

- [ ] Windows：Windows + Visual Studio 构建并在 Windows 运行，鼠标完整操作、分辨率、暂停、音频和存档可用。Mac 预览不算 Windows 通过。
- [ ] Android：完成原生包构建与真机安装，触屏、安全区、返回／退出、前后台、性能和存储可用。
- [ ] 抖音：专用构建，实际产物符合届时普通小游戏包体规则；验证开发者工具与宿主真机的首载、分包、失败重试、前后台、声音和存储。
- [ ] 三端运行同一配置和输入序列，规则结算一致；画质可以不同。每端单列通过、未通过和未测试。
- [ ] 复测核心资产缺失不误开局；需要远程资源时再确认域名、托管、缓存与费用，不擅自部署。
- [ ] 无持续内存增长、明显长时间热降频或输入卡顿；骨骼预烘焙／合批优化以实测收益为准。
- [ ] 若任一端仍受环境或性能阻塞，明确对应端未通过及处理路线，不宣布“多平台全部完成”。

- [ ] 再准备 Steam、TapTap、抖音各自的账号、必要 SDK、签名／上传材料、商店信息与审核；公开发布前核素材适用条件。
- [ ] 上传、购买、账号授权或新法律协议等实际操作在需要时确认；不从本次规划授权推定上线授权。
- [ ] 根据三波结果决定是否扩八波，再补特殊狗、投弹猫、升级／拆除和扩展波表。
- [ ] 八波才增加 39 单位压力和是否采用波前检查点的评估；不把它们变成三波范围。
- [ ] 商业化、广告收入、付费功能与经营／资质调查后置，最终发布前仍需完成所选渠道的必要确认。

## 最小记录方式

只记录当前构建、运行命令、测试日期／设备、通过或未通过项、逐波结果和具体问题。每次改规则后复测受影响项。没有运行的检查写“未测试”，不要勾选；不另外生成大量审批、证据、守卫或 hash 锁文件。规划、官方资料、概念图和实测结果分清，避免把计划写成完成。
