# 猫狗大战塔防执行清单

对应[主方案 v0.3](MVP_PLAN.md)，修订日期：2026-10-07。

当前状态：规划已编写；游戏代码、猫狗资产制作、战斗模拟和完整试玩未开始。下面所有开发／验收项均未完成，只有拿到实际结果后才勾选。

## T1. 建立独立工程与运行底座

- [ ] 在本项目中建立最小 Three.js + TypeScript 实时 3D 工程，核 Node 与依赖兼容并跑通本地构建。
- [ ] 用本机浏览器打开同一构建，实现加载、准备、暂停、继续、结算和重开状态骨架。
- [ ] 建立唯一固定步长模拟时钟，出兵／移动／冷却／前摇／飞箭／施工统一接入。
- [ ] 切后台 30 秒再返回：保持暂停，显式继续，无时间追补。
- [ ] 连续重开 10 次，检查对象、监听和事件队列，无旧局事件残留。

通过标准：最小构建可反复启动，时钟和生命周期实际通过；保留运行命令、构建结果和一次操作录像。这里不要求 TapTap 入口、安卓设备或账号审核，不安装 Android 工具链。

## T2. 验证真实猫狗与动作

- [ ] 制作或取得一猫一狗基础 GLB，记录最小来源／生成信息及使用条件待确认项。
- [ ] 在固定镜头下区分工程猫、盾猫、弩猫和普通狗。
- [ ] 验证施工、盾击、弩射、狗走路／攻击／退场，检查脚底、肩肘、持物、尺度与权重。
- [ ] 两个同类实例同时播放不同动作，姿态互不串联。
- [ ] 同一构建在本机浏览器可运行，记录角色数量与初步帧时间。

通过标准：角色与动作清晰可用，持物不明显穿帮，实例独立。白模可并行用于规则验证，但不能作为最终猫狗试玩交付。无需先生成扩展兵种或先做安卓验收。

## T3. 做通施工与经济

- [ ] 准备／战斗阶段可制造；非法阶段、错误战位、钱不够、已占位均拒绝且不扣款。
- [ ] 接受时只扣一次、只锁一次；一次只有一任务，忙时不排队。
- [ ] 前往中取消全额退款一次、解锁一次；施工开始后取消被拒绝。
- [ ] 工程猫走独立通道、不受伤不挡路；路径 ≤ 18、移速 6、施工 1.5 秒，单次目标 ≤ 4.5 秒。
- [ ] 完工前空位不参战；盾猫倒地仍占位，不能再造。
- [ ] 战斗清波时保留未完成任务；准备中继续，忙碌禁开下一波。
- [ ] 失败／胜利与完工同一步不产生幽灵单位；重开不带回旧任务。
- [ ] 首切片没有升级、拆除或支援入口。

通过标准：快速重复点击、资金不足、取消、清波、终局等操作均有唯一 taskId 与资金事件可核对；无重复扣款／退款、负余额或隐形排队。

## T4. 做通战斗、固定三波与结算

- [ ] 按主方案精确生成 8／10／12 只狗及对应出生时刻；组间空场不能提前清波。
- [ ] 盾猫最多挡 2 只；满额放行、倒地释放、前后防线独立；过线狗不被同防线回抓。
- [ ] 狗仅攻击阻挡自己的盾猫，首次等满 1 秒；盾猫只打被自己阻挡的狗。
- [ ] 弩猫按最近水晶再 spawnId 选敌；换靶不返还冷却。
- [ ] 起手／放箭前校验目标，箭绑定 targetId；线段扫掠触达碰撞代理才扣血。
- [ ] 箭目标先死、超过 2 秒、清波或终局时正确清理；每箭仅命中一次，动画不重复扣血。
- [ ] 同一步按伤害／死亡、漏怪／水晶伤害、失败、清波／胜利顺序处理。
- [ ] 每狗击败奖励仅一次，漏怪不给击败奖励，每波 +30 仅一次。
- [ ] 清波后盾猫满血复活、水晶不恢复；第 3 波胜利或生命归零失败，终局停止模拟。
- [ ] 相同配置与输入重复结果一致，暂停时前摇／冷却／飞箭／施工均冻结。

通过标准：日志能用模拟时间、实体 ID、攻击／命中／死亡／奖励事件解释画面。重点复测“最后一狗死亡／漏怪”“水晶归零与清波同一步”“多箭打同一目标”，无双结算、回抓、穿透或不可见伤害。

## T5. 验证完整对局与布阵

- [ ] 按“首波盾 + 弩，第二波加弩，第三波加盾”的候选顺序实际玩完整局。
- [ ] 每波记录采购和位置、建造时长、击败／漏怪、剩余水晶、资金和结果。
- [ ] 验证至少一条稳定通关采购路径；不能只用 270 ≤ 274 的预算算术代替。
- [ ] 做纯弩对照，判断盾猫与两道防线是否实际有用。
- [ ] 检查工程猫是否产生有意义的选择，还是明显增加等待。
- [ ] 需要调整时先改现有数值、战位与节奏，记录原因并重新测三波，不靠新增系统掩盖问题。

通过标准：真实猫狗同一构建有完整对局录像和逐波结果；混编存在可行路径，各角色作用能解释。若没通关或某兵种无价值，保持未通过，不写“玩法已验证”。

## T6. 交付本地完整试玩

- [ ] 同一构建包含桥地图、真实工程猫／盾猫／弩猫／普通狗、4 战位和完整 3 波。
- [ ] 从加载到准备、制造、开波、胜利／失败、重开均可实际操作。
- [ ] 加载失败有提示；暂停／后台返回／显式继续正确；声音随暂停处理。
- [ ] 连续重开 10 次并复测终局、取消、目标死亡等边界，无旧箭／旧任务／旧监听污染。
- [ ] 记录本机设备、系统、浏览器、分辨率、构建、首载和帧时间，说明是否达到 30 FPS 首测目标。
- [ ] 提供真实可用的本地启动说明、构建标识、完整试玩录像和必要测试摘要。

通过标准：用户能本机从头玩到结算并重开，所有关键规则有实测结果；几何体演示、素材散图、静态截图或只有可旋转模型的页面不算完成。T6 是本地切片完成，不代表公开上线、平台审核或安卓适配完成。

## T6 之后的独立事项

按实际需要推进，不反向阻塞本地制作：

- [ ] 选择最方便的可访问试玩发布方式，确认该方式需要的素材使用条件和技术限制。
- [ ] 若选择 TapTap，再核账号入口、接入形态和适用要求；若选择安卓，再决定设备验证与工具链。
- [ ] 根据三波结果决定是否扩成八波，再补特殊狗、投弹猫、升级／拆除与扩展波表。
- [ ] 在实际目标设备做性能、输入和兼容测试，不沿用本机结果冒充真机结果。

商业化、广告收入、付费功能与平台资质调查本阶段后置；公开发布前仍需完成所选渠道的必要确认，不把“暂缓”当作无条件许可。

## 最小记录方式

只记录当前构建、运行命令、测试日期／设备、通过或未通过项、逐波结果和需要修的具体问题。每次改规则后复测受影响项。没有运行过的检查写“未测试”，不要勾选；不另外生成大量审批、证据、守卫或 hash 锁文件。
