# 猫狗大战塔防主方案 v0.3

修订日期：2026-10-07

## 1. 目标与当前状态

目标是先完成真实猫狗的 3 波单机实时 3D 塔防切片，再选择方便的上线方式和后续扩展。第一交付必须可以从加载进入、下令建造、开波，一直玩到胜利或失败，再正常重开。

本次仅整理并写入规划；游戏代码、猫狗资产、战斗模拟、性能与完整试玩均未开始。下文的参数和技术是首测基线，不能当作已开发、已验证或已上线的结果。执行进度见[执行清单](EXECUTION_CHECKLIST.md)。

### 相对 v0.2 的本次修订

- 保留固定路线、固定战位、工程猫施工和 3 波完整切片。
- H5 不再是强制发布形态；本机浏览器只承担最快的制作与试玩入口。
- TapTap 账号入口、平台接入、安卓真机与原生安卓工具链移到本地切片完成后的独立事项，不阻塞 T1–T6。
- 商业化、广告收入、付费功能、平台资质调查后置；当前不购买服务、不安装 Android 工具链。
- 素材先做最小来源／生成记录；公开发布前确认适用条件。后置审查不代表获得无条件使用许可。

本版本替代此前 v0.2 中“先核 H5 入口”“T2／T6 必须先过目标安卓与 TapTap”的执行前置要求。

## 2. 第一切片范围

### 必须做

- 横屏、固定斜俯视，一张桥地图、一条固定路线、一颗猫方水晶。
- 拟人双足的工程猫、盾猫、弩猫与普通狗；角色轮廓、装备、动作能区分。
- 2 个近战位 + 2 个远程位，组成前后两道防线。
- 小鱼干单资源；制造、施工、取消与退款、阻挡与放行、实际飞箭命中、漏怪与结算。
- 3 波普通狗，数量分别为 8／10／12；准备阶段手动开波。
- 加载失败提示、暂停、后台冻结、显式继续、胜负和重开。
- 首测无广告、无内购、无账号系统。

### 本阶段不做

探索、手控主角战斗、对推、狗方基地、第二地图、随机掉落、永久养成、联网、重型通用框架，以及升级、拆除、全体加速支援。

### 后续 8 波才考虑

仍在同一地图与规则上扩到 2 近战 + 6 远程；增加投弹猫，以及冲锋狗、重装狗、精英狗；每单位一次升级和准备阶段拆除。先用 3 波实测决定是否扩展，不提前批量生产全部兵种。

## 3. 推荐制作路线

主建议：Three.js + TypeScript + GLB 实时 3D，Node 提供本地开发／构建工具，Blender 处理模型、动作、装备与导出，本机浏览器试玩。先把游戏做通，最终发布载体再按实际需要选择，不强制 H5，也不提前承诺 APK 已可构建。

开工时核对实际 Node 版本与所选依赖要求。此前只读环境检查看到 Node 20.6.0 和 Blender 4.5.13 LTS，但这不等于依赖已兼容或项目已跑通；先验证最小构建，再决定是否需要调整工具版本。

本阶段不安装 Android Studio／SDK，不把 TapTap 注册、账号权限、入口审核、平台资质或商业模式当成写代码的先决条件。若制作中出现需要购买、账号授权或发布操作的步骤，单独确认。

只保留六组职责，避免先造框架：

| 模块 | 职责 |
| --- | --- |
| Battle | 统一攻击执行、前摇／冷却、飞箭位置与碰撞、伤害／死亡／奖励事件 |
| Route／Block | 路线进度、前后防线、阻挡槽和各防线放行标记 |
| Construction／Economy | 施工状态、战位锁定与唯一资金事务 |
| Waves | 固定出兵表、未出生数／活狗数、唯一波结算和胜负 |
| Presentation／Assets | GLB、材质、飞箭显示、动作；共享资源、独立实例姿态 |
| UI／Lifecycle | 输入、加载失败提示、暂停／继续、重开和资源清理 |

规则与渲染分离。点击和 AI 只提交意图，动画负责表现，不能另外扣血或发奖。

## 4. 状态、统一时钟与结算

状态流：加载 → 准备 → 战斗 → 波结算 → 下一轮准备／胜利。水晶生命归零时立即失败，失败优先于清波和胜利。

- 每次准备由玩家手动开波，没有自动倒计时。工程猫忙碌时禁用开波按钮并显示原因。
- 只有“尚未出生数 = 0 且场上活狗 = 0”才能清波，清波奖励只发一次。
- 清波先让所有盾猫满血、倒地者复活，再开放下一轮准备操作；水晶不恢复。
- 第 3 波清波且水晶仍存活则胜利。失败／胜利后不再出生、攻击、移动、施工或发奖，只有结算 UI 和重开等非战斗操作继续工作。

### 所有战斗时间只走一套时钟

用固定步长模拟时钟，首测建议 1/60 秒；出兵、移动、攻击前摇、冷却、飞箭、施工与表现动作均消费同一模拟时间。不为每个兵种另设独立战斗定时器。

暂停或切后台立即冻结模拟与音频；返回时清空累积时间，等待玩家显式继续，不追补后台期间的战斗。重开从初始状态恢复资金、水晶、波次、角色、战位、出生编号与事件队列，清理旧飞箭、监听、计时器、对象和音频。

每个固定步内按稳定顺序处理：移动／产生攻击与命中事件 → 伤害与死亡 → 漏怪与水晶伤害 → 失败判定 → 清波／胜利判定。施工完成事件必须在终局判定后复核状态，失败或胜利同一步不允许出现幽灵完工。相同输入、配置和出生顺序应可重复得到相同规则结果。

## 5. 施工与资金边界

制造允许在准备和战斗阶段下令，暂停、波结算和终局不接受新任务；首切片无升级或拆除。一次只有一个施工任务，无排队。

1. 接受前校验阶段、资金、战位类型、占用和工程猫是否空闲。只有合法接受才扣款、锁位，并生成唯一 taskId。
2. 工程猫走独立预设通道；不受伤、不挡路、不攻击，不使用动态寻路。
3. 前往途中可以取消：只退款一次、只解锁一次，工程猫原地空闲。开始施工后不可取消。
4. 空位在完工前不参战；有效完工后才生成战斗单位，并释放任务锁。忙时点其他任务只提示“正在施工”，不扣款、不排队。
5. 已倒地盾猫仍占战位，不能当空位再造。终局取消未完成任务并停止模拟，不允许再生成完工结果；终局不再开放购买，重开直接恢复初始经济。
6. 战斗中施工遇到清波：先结算该波；未终局则保留任务并在准备阶段继续，工程猫完成或前往中取消后才可开下一波。第三波胜利则按终局清理任务。

后续 8 波若开放升级／拆除：仅准备阶段允许；升级仍走施工流程，每单位最多一次，属性在完工时更新。拆除返还总投入的 75%，向下取整；战斗中禁拆。

## 6. 阻挡、选敌和实际命中

### 阻挡和放行

每道防线独立管理阻挡名额。狗沿路线进度移动，进入防线时：有名额就分配展示槽并停住；满额就写入该防线的放行标记。已放行或被倒地盾猫释放的狗不能被同一道防线重新抓回，后方防线仍可阻挡。

盾猫倒地立即释放全部目标，本波停止工作但仍占战位；清波后满血复活。每个展示槽都须处于双方有效攻击距离内。禁止刚体互挤与动态寻路，不用碰撞推挤来制造阻挡。

盾猫只攻击自己阻挡的狗，狗只攻击阻挡自己的盾猫，不攻击远程猫。盾猫在自己阻挡的目标中按 spawnId 从小到大选敌；弩猫按“距离水晶最近，再按 spawnId”选敌。换目标不返还已经开始的冷却，不积攒空闲期间的连击。

### 弩箭必须飞到才扣血

- 起手和发射前都验证目标存活且处于射程内；发射前失效就取消这一箭，不返还已开始的攻击间隔。
- 每箭有唯一 projectileId、锁定 targetId 和已命中标记。按当前目标位置追踪，不换靶、不用刚体；发射后允许追到射程外。
- 以本步前后位置作线段扫掠，触达目标碰撞代理半径时才产生统一伤害事件，避免高速穿透。代理半径须是明确配置并与模型尺寸核对。
- 目标先死或箭存活超过 2 秒时消散，不凭动画完成回调补伤害。
- 同箭至多提交一次命中和一次伤害；死亡、击败奖励也按唯一实体 ID 去重。
- 清波、失败、胜利和重开清空飞箭与待命中事件；暂停冻结前摇、冷却和飞行。

近战同样由 Battle 按模拟时间判定伤害，动作不另算一次。狗首次攻击也必须等满 1 秒，不能在阻挡瞬间凭空多打一击。

### 经济仅证明“买得起”

假设前波全部击败、无漏怪，各波开始前累计可分配收入为：

- 第 1 波前：160。
- 第 2 波前：160 + 8 × 3 + 30 = 214。
- 第 3 波前：214 + 10 × 3 + 30 = 274。

首测采购候选：第 1 波前盾 + 弩花 135，余额 25；第 2 波前再造弩花 75，余额 4；第 3 波前再造盾花 60，余额 4。总投入 270 ≤ 274。

这些数值只是条件预算。漏怪会减少击败收入；射程覆盖、建造时间、阻挡和伤害时序均未实测，因此不能据此宣称能通关。必须用完整对局和逐波结果证明采购路径可行。

保留原 8 波方案的算术记录：击败奖励合计 524，全局累计收入 924，第 8 波前累计收入 750，2 盾 + 3 弩 + 3 投弹全部升满成本 1085。这些是此前方案的经济复核，不是本次 3 波配置，也不是 8 波已能通关的证据；扩展前须重新落实各特殊狗规则、波表和可行采购路径。

## 8. 资产与性能

先验收一只猫基础体和一只狗基础体，再用装备区分猫的工作。约 4.5–5 头身拟人双足，简化手、毛发和衣服，不做耳尾物理或布料模拟。

角色、装备、场景分开制作。优先验证工程施工、持盾攻击、弩射，以及狗的走路／攻击／退场。检查脚底、肩肘、持物、坐标轴、尺度、权重、材质槽和镜头辨识度。两个同类实例必须可同时播放不同动作，不能因为共享骨架资源而共享同一实时姿态。

最小来源记录直接随资产信息保存：资产文件或 ID、来源／生成工具、生成或获取日期、输入参考来源、适用条件链接及待确认项。不另建大套审批文件。来源或条件尚未确认的素材先标记，不作为可公开发布素材；不假定后续付费自动覆盖旧资产。

初始参考预算为每角色约 3000–6000 三角面、尽量共享材质、1024 级身体贴图和简化地面影。先在本机真实构建中测表现；30 FPS 是首测目标，不能写成已达到。记录设备、系统、浏览器、分辨率、构建、首载时间、帧时间和连续重开情况。

8 波扩展再测试 30 狗 + 8 战斗猫 + 1 工程猫压力场景。遇到卡顿先定位模型、材质、阴影、特效、骨骼更新，若减少同屏敌人要同步重审波表与玩法。

## 9. 执行顺序与完成标准

T1 运行底座 → T2 真实猫狗资产样本 → T3 施工与经济 → T4 战斗与三波 → T5 完整对局与布阵 → T6 本地可玩交付。T2 资产验证可以与 T3／T4 的白模规则验证并行，最终以同一真实猫狗构建验收。

T6 完成至少意味着：一张桥地图、可辨识猫狗、全部 3 波、胜负、重开、暂停／后台恢复、加载失败提示均可实测；提供启动说明与完整录像，关键边界测试有实际结果。运行命令由实现后的真实工程确定，不在空仓库预写不存在的启动命令。

核心测试必须覆盖：重复下单与取消不重复扣款／退款；盾满额放行和倒地释放；过线敌人不回抓；箭实际命中和目标先死；组间空场不提前清波；漏怪与击败不双发奖；水晶归零与清波同一步只失败；终局无幽灵施工；暂停与后台无追补；连续重开无旧事件污染。

具体勾选项见[执行清单](EXECUTION_CHECKLIST.md)。用必要日志、完整录像和简短逐波表说明结果即可，不生成大量证据包、守卫脚本或 hash 锁。

## 10. 本地通过后的发布与扩展

1. 先选择最容易交付的可访问试玩方式，检查该方式需要的素材使用条件和实际技术限制。公开发布之前完成这些必要确认。
2. 如需 TapTap、移动端或原生包，再单独处理对应入口、账号、资质、设备测试和工具链；不能把本地浏览器运行当成平台已通过或 APK 已就绪。
3. 根据 3 波的通关、工程等待和兵种价值决定 8 波扩展。
4. 商业化、广告收入、付费功能与经营层面的调查留到后续，不阻塞当前本地制作；不承诺收入、留存或未经验证的上线工期。
