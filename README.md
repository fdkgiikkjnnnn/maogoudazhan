# 猫狗大战塔防

先做出一局能从头玩到胜负结算的猫狗塔防，再扩内容、分别交付多平台版本。

当前主方案：**v0.4，2026-10-07 修订**。本仓库目前只有规划文档，尚未开始游戏代码、猫狗资产制作或可玩构建；没有已上线版本。当前工作是把设计和风险处理写清楚，开发另行开始。

## 第一版要做成什么

一张桥地图，一颗需要守住的水晶；拟人双足的工程猫、盾猫、弩猫和普通狗；2 个近战位、2 个远程位；8／10／12 只普通狗组成的 3 波；制造、施工、实际命中、漏怪、胜负、暂停和重开形成完整闭环。

首次正式试玩要有能看清动作的真实猫狗模型。白模可以验证规则，概念效果图可以确认目标画面，但两者都不能代替完整猫狗试玩。效果图是设计参考，不能当作游戏截图或已实现证明。

## 多平台路线

采用 **Cocos Creator 3.8 LTS + TypeScript + 实时 3D**，Blender 制作源资产，glTF／GLB 作为交换资产。共用纯 TypeScript 玩法核心、Cocos 表现层和 PlatformAdapter 平台适配层。

- Windows 原生版本 → Steam
- Android 原生版本 → TapTap
- 抖音小游戏专用构建 → 抖音

同一源工程分别构建、分别测试；不是一个包直接跑遍三平台。Mac 用于日常制作；Windows 原生编译与验收需要另行准备 Windows + Visual Studio 环境。

## 当前优先级

1. 先定规则、视觉方向、跨平台边界和风险处理，再经确认开始开发；本轮不安装软件、不写游戏代码、不部署。
2. 先完成 3 波完整切片。输入、屏幕安全区、生命周期、存档边界和资源预算从第一天纳入设计。
3. 平台上传、账号、SDK、商店素材和审核放在游戏完成后的独立阶段；商业化、广告收入、付费与资质调查继续后置。必要的技术限制现在查清，避免最后重做。
4. 素材保留最小来源／生成记录，公开发布前确认使用条件。是否扩成 8 波，由三波实测决定。

参数与性能预算均是待验证基线；预算算术不等于通关结果，官方支持某平台也不等于本项目已跑通。以[执行清单](docs/EXECUTION_CHECKLIST.md)记录真实状态。
